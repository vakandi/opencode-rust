that nobody renamed into place.

A corrupt `message` b-tree produces hangs, failed reads and phantom "idle" sessions on
exactly the query path every session depends on. That is a *much* better candidate for a
"20-session stall" than a language, and it is a **10-minute fix**: stop the container, move
the corrupt file aside, rename `opencode.fixed` → `opencode.db`, start, measure.

**Therefore: no member of this team may responsibly recommend a rewrite yet, and I include
myself.** Before any port decision, someone must (1) restore the clean DB, (2) start the
container, (3) capture `docker stats` + `/proc` + a heap snapshot at the point of stall.
