## 🚀 PHASE 0 - RECHERCHE 21ST.DEV (MANDATORY AVANT TOUT)

**RÈGLE ABSOLUE: Avant chaque création, refonte, ou construction de composant/section/page/site, tu dois IMPÉRATIVEMENT effectuer une recherche approfondie sur 21st.dev.**

### Pourquoi cette phase est CRITIQUE

21st.dev est la référence premium pour les composants React/Tailwind/Framer Motion. Chaque semaine, des centaines de développeurs partagent des composants de haute qualité avec des animations fluides, des interactions modernes, et des designs qui convertissent.

**Tu dois être un analyste expert de cette plateforme, pas un développeur qui code en vase clos.**

### Quand activer cette phase ?

Cette phase s'active pour TOUTE demande de :
- Création de composant, section, page, site
- Refonte de composant, section, page, site
- Amélioration de composant existant
- Construction from scratch

### COMMENT RECHERCHER - Protocole d'Analyse 21ST.DEV

#### Étape 1: Recherche Multi-Angles
Utilisez les outils Magic MCP disponibles pour rechercher sur 21st.dev :

```bash
# Types de recherches à effectuer (TOUTES obligatoire):
1. "trending" - Composants les plus populaires de la semaine/mois
2. "community" - Composants validés par la communauté
3. "newest" - Derniers composants récents
4. "[catégorie spécifique]" - Hero, pricing, testimonials, CTA, etc.
```

#### Étape 2: Analyse Qualitative (NE PAS SE LIMITER À LA FORME)

Pour CHAQUE composant trouvé, évalue:

| Critère | Question à se poser | Pondération |
|---------|---------------------|--------------|
| **Fluidité** | L'animation est-elle naturelle ? Perturbante ? | 20% |
| **Conversion** | Ce composant pousse-t-il à l'action ? | 25% |
| **Pertinence** | Correspond-il au contexte business ? | 20% |
| **Qualité Code** | Le code est-il propre, maintenable ? | 15% |
| **Originalité** | Apporte-t-il quelque chose de nouveau ? | 10% |
| **Modernité** | Est-ce un pattern actuel ou daté ? | 10% |

#### Étape 3: Cross-Referencing
- Regarde les **composants du mois** sur la page community
- Regarde les **témoignages** (comments/avis des utilisateurs)
- Regarde les **variantes** proposées par les créateurs
- Identifie les **patterns récurrents** qui fonctionnent

#### Étape 4: Adaptation Contextuelle
Un composant 21st.dev n'est jamais copié-collé DIRECTEMENT. Tu dois:
1. **Comprendre** le pattern et son intention
2. **Adapter** au contexte business (couleurs, typography, spacing)
3. **Améliorer** si possible avec tes propres trouvailles
4. **Intégrer** de manière cohérente avec le reste du projet
